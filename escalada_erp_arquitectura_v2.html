DIAGNÓSTICO RAÍZ DEL PROBLEMA RELACIONAL: El schema Prisma sí tiene FK correctamente definidas entre todos los módulos. El problema es que el seed y el frontend usan datos no sincronizados que no respetan la cadena completa usuario → escalador → inscripcion → cohorte ← [programa · ciclo · muro · entrenador]. Resultado visible: un escalador aparece "activo" sin inscripción real, grupos sin sesiones, pagos sin inscripción vinculada. La solución no es cambiar el schema — es un seed coherente que llene las tablas en orden respetando FK, y un frontend que consulte los datos reales en lugar de usar mock data estático. Una inscripcion sin pago nunca debería llegar al frontend: usar transacción Prisma prisma.$transaction([inscripcion.create, pago.create]) garantiza atomicidad.
